# Reachability Is Not Consequence — Reproducibility Repository

Code, figures, and data for *"Reachability Is Not Consequence: Consequence-Aware
Prioritization of Identity Risk in Cloud-Native Infrastructure"* (IEEE IEMCON 2026).

**Author:** Prawal Pokharel · Iverson Cloud
**Patents:** aspects covered by pending U.S. applications No. 19/641,446 and No. 64/138,302.

The paper formalizes **identity blast radius** — the consequence of compromising an
identity, obtained by joining the authorization graph to the runtime
service-dependency graph and propagating consequence along three channels
(availability, confidentiality, integrity). It shows that reachability-based risk
ranking (permission/privilege/reachable-resource counts) systematically misranks
identity risk, and validates the consequence-aware alternative against three tiers of
ground truth of increasing realism.

## Evidence tiers

| Tier | Ground truth | Scripts |
|------|--------------|---------|
| **A — synthetic** | exact consequence from a seeded generative model | `estate.py`, `methods.py`, `run_e2.py`, `run_e3_e5.py`, `run_e7.py`, `run_e12.py` |
| **B — production engine** | Iverson Cloud dependency engine over 5 real topologies | `engine_harness.py`, `run_e8_real_engine.py`, `run_e9.py`, `run_e10_e11.py` |
| **C — live cluster (observed)** | real availability fault injection, real credential/integrity compromise, off-distribution app | `tierc_real_v6.sh`, `analyze_tierc_real.py`, `ci_experiment.py`, `integrity_experiment.py`, `bookinfo_experiment.py` |
| C&nbsp;model extensions | 3-channel C/I model, capability severity | `extensions.py`, `run_ext.py` |

Tier C is the key methodological contribution over the accepted version: ground truth
is **observed system behavior**, not the engine's own computation, which removes the
computed-oracle circularity for the availability, confidentiality, and integrity
channels, and reproduces the availability result on an off-distribution application.

### Key scripts

- **`run_ext.py`** — E13 (confidentiality/integrity channels) and E14 (capability
  severity: second-order for availability, first-order for confidentiality). Uses
  `extensions.py`.
- **`tierc_real_v6.sh`** — real fault injection on a live Online Boutique running on
  `kind`: scales each service to zero (waiting for **0 running pods**, since a
  scaled-down pod keeps serving through its graceful-shutdown window) and probes the
  real frontend over HTTP from an in-cluster pod (`probe_inner.sh`). Restores and
  re-baselines between kills, clearing stale gRPC channels. Output →
  `data/tierc_fault_injection_results.csv`; analyzed by `analyze_tierc_real.py`
  (confidence-aware ρ = 0.987 vs naive static graph 0.778; 8/10 exact broken-flow-set
  match; identity-level ρ = 0.958).
- **`ci_experiment.py`** — real confidentiality-compromise: creates Secrets,
  ServiceAccounts, and RBAC on the live cluster and "compromises" each identity by
  **actually reading** the secrets its credentials reach (`kubectl auth can-i` /
  `get secret --as`), chaining laterally. Includes 3 planted over-privilege
  misconfigurations. RBAC-aware confidentiality score reproduces the measured
  exfiltration (ρ = 1.00) where a dependency-only view (ρ = 0.691) misses the
  misconfigs; a read-only agent identity exfiltrates 0 secrets. Tears down the
  namespace on completion.
- **`integrity_experiment.py`** — real integrity-compromise (the dual of confidentiality):
  real ConfigMaps as data-of-record + real UPDATE RBAC (+ planted write-misconfigurations);
  "compromise" each identity by actually corrupting the data it can write and measure the
  corruption reach up the dependency graph. RBAC-aware integrity score reproduces the measured
  reach (rho=1.00) where a dependency-only view (rho=0.259) misses the write-misconfigs; the
  read-only agent corrupts 0 stores.
- **`bookinfo_experiment.py`** — OFF-DISTRIBUTION fault injection on Istio Bookinfo (an app the
  dependency heuristic was never tuned on): the productpage renders (HTTP 200) when details or
  reviews are removed and only goes down when the productpage itself is removed — the
  confidence-aware prediction matches all cases, the naive static graph over-predicts.
- **`run_tierc_mesh.py`** — a controlled process-mesh replica of the Online Boutique
  topology (pure Python, no cluster), a lighter-weight cross-check of the fault
  injection result.

## Reproducing

Tier A/B and the model extensions are pure Python:

```bash
pip install -r requirements.txt
cd experiments
python run_e2.py        # synthetic ranking fidelity (Fig. 1)
python run_ext.py       # E13/E14 confidentiality + capability severity
python make_figs.py     # regenerate Tier A/B figures
```

Tier C needs a local Kubernetes cluster (`kind`) running Google's
[Online Boutique](https://github.com/GoogleCloudPlatform/microservices-demo) in the
`default` namespace, with `kubectl` pointed at it:

```bash
cd experiments
bash tierc_real_v6.sh                 # real fault injection -> data CSV
python analyze_tierc_real.py /tmp/tierc_real_v6.csv
python ci_experiment.py               # real credential-compromise (creates + tears down ns ci-exp)
```

All Tier A/B results regenerate deterministically from fixed seeds.

## Building the paper

cd paper
tectonic paper.tex     # or: pdflatex paper.tex
